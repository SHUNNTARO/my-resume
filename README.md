# 内容

### 概要
HTTPは、インターネット上での通信のために最も一般的に使用されるプロトコルであり、安全で信頼性の高いパケットの送受信を可能としているためクライアントやサーバなどの多くのアプリケーションが使うアプリケーション層で標準化されている。
## HTTP

* https(http): どのように通信するか
* kakkeeess-website: どのサイトに行くか（ドメイン名）
* com: (topドメイン)
  
上記のことを示している。
### CRUD操作
データベースとの間で情報を読み取り（Read）、作成（Create）、更新（Update）、そして削除（Delete）これらの一連の操作をCRUD操作という。

| HTTPリクエスト  | 機能 |
| ------------- | ------------- |
| GET | **READ**: リソースからデータを要求する。|
| POST  | **CREATE**: リソースを更新するためにデータをサーバに送信する。|
| PUT  | **UPDATA**: 新しいリソースを作成するか、既存のリソースを置き換える。 |
| DELETE  | **DELETE**: 指定したリソースを削除する。|

### HTTPレスポンス
**<ins>ステータス行</ins>**


* HTTP ステータスコードは、レスポンスの種類を表し、5つにカテゴリ分けされる。

| HTTP ステータスコード  | 機能 |
| ------------- | ------------- |
| 1xx（情報） | 途中経過を示すレスポンス。|
| 2xx（成功  | リクエストが成功したことを表すレスポンス。|
| 3xx（リダイレクト）  | 追加のアクションが必要なことを示すレスポンス。 |
| 4xx（クライアントエラー）  | クライアントのリクエストに問題があることを示すレスポンス。|
| 5xx（サーバエラー）  | サーバ側に問題があることを示すレスポンス。|

## 開発環境
**仮想マシン**

* 仮想マシンは、物理的なコンピュータをソフトウェアレベルでエミュレートすることができ、これにより、一つの物理的なサーバやホストマシン上で複数の OS を同時に実行することが可能となる。また、各仮想マシンは独立した環境として動作し、それぞれが独立した物理マシンであるかのように、自身の OS やアプリケーションを実行することも可能とする。

**クラウド仮想マシン**

* 停電やインターネット接続の問題、アプリケーションのスケーリングに伴うパフォーマンス問題により、パーソナルコンピュータやデスクトップなどの個人的な環境で仮想マシンを稼働させても、そのような環境は通常、商用の要求を満たすことは難しい。そのため強固なインフラストラクチャが必要となりその代替品として使用されているのがクラウド仮想マシンである。
